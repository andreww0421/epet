# ePet 臺灣封閉試點：先驗證需求，再決定收費 MVP

日期：2026-11-25。狀態：**研究與驗收設計；尚未執行試點，尚未核定售價或容量**。

本計畫針對 1–3 家臺灣補習班或個別教師，先確認真實工作流程、導入成本、持續使用理由與付款決策。現有程式與測試只能證明已有能力，不能替代客戶需求或付款意願。需求訪談、實際試用、可信的時間基線及付款決策證據目前皆為 **UNKNOWN；已驗證需求樣本 0**。不得把本文件的目標、假設、合成測試或價格題目寫成實際成果。

本次只形成可審閱文件，不聯絡客戶、不招募、不新增真實帳號或學生、不啟用收集、不部署、不套 migration、不串付款。工作區既有前端與測試修改保留。後續真人研究、真實資料試點及收費發布各自需要完成本文對應門檻。

## 1. 要回答的決策

1. 教師最近一次實際教學管理，哪個步驟反覆耗時或容易出錯？ePet 是否能替代其中一個完整流程？
2. 每個工作區的使用中班級、班級名冊人次、教師寫入席位、歷史紀錄及每週操作量是多少？現有儲存模式是否能支持這個使用形態？
3. 使用者、管理者、付費者是否同一人？誰有採購權、學生資料處理授權、預算及停止使用的決定權？
4. 教師是否能在適當權限內完成導入、確認保存並在下一次教學回來使用？需要多少人工協助？
5. 在展示實際價值、容量及服務邊界後，付款決策者會採取什麼可核對的下一步？

1 家願意持續合作的學校可支持下一輪「該情境的需求驗證」，不能證明臺灣市場、普遍轉換率或可規模化營收。若沒有實際合作對象，先停在研究準備，不以功能開發填補需求空白。

## 4. 研究同意、教學資料與分析分開

- **教學必要處理**：只有校方／有權人完成資料處理授權、保存／退出說明、權限分工與必要合約核對，才考慮放入真實學生資料；先以合成班級演練。學生／家長獨立登入、全班 viewer 代替個人入口都不在本試點範圍。
- **選擇性研究**：另以清楚的研究邀請取得明確 opt-in，可拒絕單題或退出，產品使用與支援不得以同意研究為條件。預設只採人工紀錄的時間、任務結果、協助次數及非識別事實摘要；不錄影、不錄音、不截圖、不拿真實畫面／報告／console／network logs 回傳、不開 replay 或 autocapture。
- **選擇性 product analytics**：維持現有關閉狀態；若日後另核准啟用，遵守 DNT／GPC、環境隔離、enrollment、k 抑制與保留政策。人工研究不是繞過訊號的方法：不從 opt-out 使用者的日誌、DB、session 或監控補算行為、不要求關閉隱私訊號。只有使用者另行自願參與的訪談／人工任務回報，才依該研究同意記錄。
- **必要帳務／安全稽核**：未來若收費，訂單、付款狀態、退款與授權變更須有自己的必要、最小、可稽核資料契約與保存目的；不得依 optional analytics 計費或以 DNT／GPC 作為停用必要交易紀錄的理由。當前沒有因此新增任何收集。

研究保存提案：原始去識別摘要限研究負責人與指定決策者存取，試點結束後 30 天內複核，最遲 90 天刪除或重新取得具體保存理由；只保留必要的非識別決策結論。同意撤回如何定位、刪除與回覆須先定義，已無法分離的彙總要如實告知。此為待核准研究政策，**不是現有自動 purge 或對平台備份的刪除承諾**；教學資料、必要 audit 與未來帳務各依其核准政策處理。

| 試點窗口 | 一位產品／研究負責人：邀請、告知、需求帳本、試用期限與退出確認。 | 臺灣工作日 09:00–18:00 收件，下一工作日前確認已受理；先向參與者說明，不能當已簽約 SLA。 |
| 技術接手 | 一位工程負責人及可連絡備援：保存、權限、登入、容量、同步故障與已知事件。 | 在約定服務時段，疑似越權／遺失立即暫停受影響使用並優先接手；恢復時間 unknown，不承諾未演練的 RTO。 |
| 資料／隱私 | 一位營運者指定窗口：資料授權、請求驗證、保留、退出、事件通知及備份例外。 | 依核准程序回覆案件時程；未指派或程序未備妥則不開真資料試點。 |

回報表只需要隨機案件代碼、產品版本、概略任務、固定錯誤碼／狀態、發生的大致時間與是否仍阻擋。診斷代碼如尚未實作可用人工案件碼，不能聲稱已有跨 request correlation。**不要索取 session cookie、Token、CSRF、密碼、邀請連結、raw request／response、學生姓名、成績、評語、截圖或 console/network logs。** 若需要深入排查，先用合成重現與受限的既有 categorical diagnostics；客服不登入冒用教師、不新增未受控 impersonation，不能讓教師把整班匯出寄到工單。

### 停止與重開表

| 觸發 | 立即處理 | 重開必要證據 |
| --- | --- | --- |
| 跨租戶／越班資料、錯帳號草稿、降權後仍可見、viewer 可寫或角色繞過。 | 停受影響試點寫入／分享與擴邀，依事故程序控制存取並撤銷受影響 session；保留最小必要 audit，不向工單複製教學資料。 | 修補後合成越權、scope／generation、角色與同帳號合法控制均通過；負責人核准重開。 |
| 顯示成功但重載資料消失、重複獎勵、衝突覆寫、部分保存或無法安全退出。 | 停受影響寫入與新導入，不以分析 ACK 安撫；保留受控草稿，依既有 conflict／retry 流程，不能自動丟棄資料或重播全量。 | 原觸發情境、lost response、CAS、離線、重載與恢復均重驗；使用者確認應保留資料。 |
| 容量逼近／413、持續重試、歷史成長或並行成本超出可承擔範圍。 | 停新增範圍與容量承諾；使用既有有界重試、清楚拒絕／匯出／採用遠端機制。 | 合成同等歷史負載成功；明訂可用容量及超限路徑。不得提高 guard、刪歷史或裁切學生來過關。 |
| 無授權真實資料、錯誤分享、分析／監控含敏感內容、不同意研究仍被記錄。 | 停該收集／分享與研究，隔離受影響紀錄，轉隱私窗口按既有程序處理。 | 消除來源、權限／allowlist／同意與刪除驗收；通知與必要紀錄依核准政策完成。 |
| 無人接手、寄信／通知失效、隔離 staging 不明、備份／復原 gate 未完成。 | 停邀請與真資料導入；提供已核准的退出／匯出說明，不承諾服務持續可用。 | 真實資源與通知接收、具名接手、有計時復原／刪除重套證據。 |
| 多次教學機會仍無使用、無明確問題或無可行付款／資料授權鏈。 | 停止功能擴張；訪談確認原因，參與者可退出。 | 取得新的具體需求證據才另定一輪，不延長試用掩蓋無需求。 |

分析若日後另獲核准啟用，停止時先關 client build flag 與 server enabled flag、清理舊 scope pending；保留 additive tables，不 drop DB、不 rollback migration ledger、不重播歷史學生資料補數。應用回復採與已擴充 schema 相容的已審版本；真實 D1 復原是獨立核准、隔離演練的程序。暫停試用不是資料自動刪除；退出、教學資料請求、研究撤回、下載副本與備份限制分別交代。
